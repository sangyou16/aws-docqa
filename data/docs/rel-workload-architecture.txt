Title: Reliability: workload architecture
Source: https://docs.aws.amazon.com/wellarchitected/latest/framework/workload-architecture.html
Note: Seed paraphrase written for this project; run scripts/fetch_corpus.py to replace with the page text.

A reliable workload starts with up-front design decisions for both software and infrastructure, such as how the workload is segmented into services.

Design interactions in a distributed system to prevent failures: identify which kind of distributed system is required and implement loosely coupled dependencies, for example with queues.

Design interactions to mitigate or withstand failures: make operations idempotent, control and limit retry calls using exponential backoff and jitter, set client timeouts, and degrade gracefully when dependencies fail.
